# Spec — 서버리스 웹앱 리뉴얼

기존 Streamlit + RunPod 상시 GPU 구조를 웹 + 상태 없는 API + 안 쓸 때 0대가 되는 추론 서버로 다시 구성한다. 파인튜닝한 STT·TTS 모델, 500개 레시피 데이터, 대화 흐름(상태 기계)은 그대로 두고 서빙과 연결 방식만 바꾼다.

## Why

- **페르소나**: 포트폴리오로 서비스를 보는 평가자(가끔 한 명씩 접속)와 운영하는 팀원
- **상황**: 사용자가 거의 없는 기간에도 서비스는 떠 있어야 하고, 접속하면 바로 써 볼 수 있어야 한다. 서버는 개인 PC가 아니라 클라우드에 있어야 한다.
- **문제**:
  1. RunPod A40(48GB) 상시 과금 — 쓰는 사람이 없는 시간에도 비용이 나간다.
  2. Streamlit 재실행 + WebRTC 구조에서 화면 잔상, Queue overflow, 동시 1~2명 한계가 반복됐다.
  3. 대화 상태가 Streamlit 세션에 있어 서버를 늘리거나 재시작하면 이어지지 않는다.
  4. 공개 서비스에 로그인 없이 GPU를 호출할 수 있어 남이 비용을 만들 수 있다.
- **측정 지표**: 사용 없을 때 월 비용 0원 근접, 콜드 스타트 시간을 숨기지 않고 안내, 동시 사용자 증가에도 한 사람의 등록 작업이 다른 사람의 조리를 막지 않음

## Goal

- **해결 목표**: 웹(Vercel) + API·STT·TTS(Modal, 마지막 요청 뒤 5분이면 0대) + DB·파일·로그인(Supabase)으로 옮기고, 로그인한 사용자만 쓰게 한다.
- **성공 기준**: AC 표 참고
- **Out of Scope**: 재료 대체·타이머·바지인(기존과 동일), 관리자 페이지와 화자검증(리뉴얼에서 제거), 요리명 추정 LLM(제거, 정확도 비교는 별도 작업), 레시피 1,000개 확장, 결제

## What

**Happy Path**
1. 웹을 열면 로그인 화면(구글 우선, 이메일은 시트)만 보인다. 서버는 비로그인 요청을 401로 거절한다.
2. 로그인 후 "시작하기"를 누르면 마이크를 연결하고 STT GPU를 미리 깨운다.
3. 브라우저가 말소리를 잘라(VAD) WAV로 보내면 API가 STT(L4)로 글자로 바꾸고, 요리명 매칭과 임베딩 의도분류로 레시피를 찾는다.
4. 대화 상태는 Supabase `sessions`에 저장되고, 응답 문장은 미리 만든 mp3가 있으면 그 파일을, 없으면 실시간 TTS(L4)를 재생한다.
5. 레시피 등록은 글자로 입력한다(마이크는 닫힘). 저장하면 등록 음성이 별도 GPU 함수(동시 1대)에서 만들어지고, 화면에 "보통 1~3분" 안내와 완료 표시가 뜬다. 음성은 본인만 들을 수 있다.

**Edge Cases**

| # | 상황 | 처리 방식 |
|---|---|---|
| EC-01 | 비로그인 요청 | 모든 엔드포인트 401 `login_required`(health 제외). `warmup`은 GPU를 깨우지 않음 |
| EC-02 | 콜드 스타트 | 요청이 2초 넘게 걸리면 "서버를 깨우는 중" 안내. 첫 요청 약 20초 |
| EC-03 | 채팅·폼에 공격 문구·긴 글·이상한 형식 | `guard.py`가 정리·제한·차단. 채팅은 기록·조회 없이 안내만, 반복하면 세션 차단 |
| EC-04 | 마이크 권한 없음·연결 실패 | 오류 안내 + 글자 입력·버튼으로 계속 가능 |
| EC-05 | 미리 만든 음성이 없는 문장 | 실시간 TTS. 실패하면 글자만 보여 줌 |
| EC-06 | 동시에 여러 명이 레시피 등록 | 등록 음성 생성은 동시 1대 큐. 조리 중인 사용자의 STT·TTS와 별도 함수 |
| EC-07 | 서버 재시작·컨테이너 교체 | 대화 상태가 DB에 있어 이어짐 |
| EC-08 | 남의 레시피 접근 | 404(없음과 동일, IDOR 방지) |
| EC-09 | 사용자 등록 하루 한도 초과 | 안내하고 저장하지 않음(`REGISTER_DAILY_LIMIT`) |
| EC-10 | Modal 무료 크레딧 소진 | spend limit $0이라 카드 청구 없이 작업이 멈춤 |

## How

- 구성: `web/`(Vite+React), `server/chefear_api`(FastAPI, 상태 기계 `service.py`), `inference/modal_app.py`(Stt·Tts·RecipeAudio), `db/migrate_renewal.sql`, `renewal/API_CONTRACT.md`, `renewal/DEPLOY.md`.
- 기존 `orchestration/`(레시피 검색·등록·의도분류), `stt/`, `tts/`는 그대로 재사용한다. STT 후처리는 `src/stt/postprocess.py`로 분리해 로컬과 Modal이 같은 코드를 쓴다.
- 음성은 문장 지문(`sha256(VOICE_VERSION + 문장)`)으로 미리 만든 mp3를 찾고(`scripts/upload_tts_audio.py`), 없을 때만 TTS GPU를 쓴다.
- 제거: Streamlit 앱(`src/app.py`, `src/ui`, `ui/`), RunPod·Docker·GHCR 배포, 소개 페이지(`landing/`), GPU 워커 풀, 관리자 화자검증, 로컬 계정 모듈(`orchestration/auth.py`, Supabase Auth로 대체).
- 입력 방어: `server/chefear_api/guard.py`(정리·길이 제한·공격 문구 차단) + 구조적 방어(파라미터 쿼리, React 이스케이프, 로그인 전용, 본인 소유만 접근).

## AC

| # | 기준 | 상태 |
|---|---|---|
| AC-01 | 비로그인은 서비스 전체가 401, GPU 깨우기도 못 함 | 구현·테스트·배포본 확인 |
| AC-02 | 글자 입력으로 조회→확인→조리 단계 이동이 서버(Modal)·DB(Supabase)로 동작 | 배포본에서 브라우저 자동화로 확인 |
| AC-03 | 음성(마이크→STT→응답→재생) 전체 흐름 | **실제 사람이 끝까지 돌려 본 기록 없음.** 가짜 마이크로 연결·해제, VAD 감지·업로드까지 확인(STT 응답은 GPU가 다른 작업에 차 있어 시간 초과). 응답 음성 재생은 배포본에서 확인 |
| AC-04 | 레시피 등록→본인 전용 음성 생성→마이레시피 반영, 준비 안내 | 구현·화면은 데모 모드로 확인. 실제 Modal 음성 생성 시간(보통 1~3분은 추정)은 **미측정** |
| AC-05 | 안 쓸 때 0대, 마지막 요청 5분 뒤 내려감 | 설정(`scaledown_window=300`)과 컨테이너 목록으로 확인 |
| AC-06 | 사용 없을 때 카드 청구 없음 | spend limit $0 설정 확인, 이번 달 청구 $0.00 |
| AC-07 | 공용 음성 2,724개 업로드로 실시간 TTS 호출 최소화 | 2,724개 업로드 완료(2026-10-20). 표준 레시피 500개의 확인·단계 문장과 고정 안내 전부 파일 있음, 배포본에서 실시간 TTS 호출 없이 재생 확인. 끝 잘림 의심 204개는 사람이 안 들어 봄 |
| AC-08 | 종단 응답 시간(p95)·동시 사용자 부하 | **미측정** |
| AC-09 | 요리명 LLM 제거가 인식 정확도에 준 영향 | **미측정**(같은 발화 세트로 A/B 필요) |
| AC-10 | 테스트 | `pytest tests`(GPU·DB·모델 불필요) + CI(`.github/workflows/ci.yml`) |
